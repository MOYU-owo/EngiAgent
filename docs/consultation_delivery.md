# 专家咨询与机制对照：实现、使用和验证

> 2026-11-02更新：工程入口现已统一为CN，旧分支已移除，见[CN迁移与验证](cn_only_migration.md)。以下实验和验证数字保留原批次记录。

日期：2026-10-27。本文件描述本轮实际新增的能力。此前同日的专家评审和文献对照是实施前快照。

## 1. 本轮完成

### 专家咨询

新增“专家咨询”工作区。先运行一个中国规范案例，再提问。

- 解释当前抗弯、抗剪、构造、裂缝、长期挠度检查；列出实际值、失败原因、已记录依据及现有 LaTeX 公式。
- 回答当前实际的工具执行/缓存记录和修订历史。
- 对成本与施工问题给出有边界的策略方向，不输出没有成本模型支持的节约金额或最优结论。
- 从当前问题提取明确的参数修改，逐项展示原值、标准化新值、单位和原文。
- 建议与原计算结果绑定；采用后形成未确认草稿，回到工作台确认后才能运行。
- 修改新设计时保留已算出的实配截面、根数及箍筋，转为已有梁验算；不偷偷重新选筋，不自动减少原验算项目。
- 旧建议、重复采用、未完成的新草稿、直接内力与荷载变更冲突均有检查。
- 咨询历史和实际调用审计随审计 JSON 导出。会话仍在内存，不宣称跨进程持久化。

没有照搬原论文“自由生成计算—模型纠错—模型整合”三 LLM 管线。本版用一次结构化模型请求理解问题及提取修改，程序根据真实工具记录组织解释；新数值仍必须由工具重算。这使支持范围和数值来源更容易复核，也意味着它不是开放式规范问答或完整工程专家。

### 减少低价值模型调用

侧栏新增“DeepSeek · 仅需求与咨询”：

- 自然语言任务由真实 Dispatcher 提取。
- 专家咨询由真实结构化模型解析。
- Design/Evaluation 由生产用 `ProgramRoles` 按工程 DAG 执行，不调用模型复述既定计划。
- 保留原来的全模型模式，便于后续比较；离线模式仍明确标为固定角色/有限规则咨询。

本轮没有实测两种模式的网络延迟或成功率优势，因此只声明省去了相应模型请求，不提供虚构的提速比例。

### 同内核机制对照

新增可执行实验，比较：

1. full：每次执行完整五项验算，不复用缓存。
2. dag：只执行请求目标相关节点，不复用缓存。
3. dag_cache：只执行目标相关节点，并使用输入/版本有效的缓存。

覆盖两种自重约定、完整/局部抗弯两个目标、梁高/活载/裂缝限值/根数/无变化五种修改，共20种组合；每组重复3次，总计180次运行。保存原始输出、输入与源文件哈希、实际执行/复用数、墙钟时间及运行环境。各组轮换执行顺序。

## 2. 本轮实际实验结果

本次在完整测试结束后单独运行实验：

|组别|运行次数|执行节点合计|复用合计|单次耗时中位数|
|---|---:|---:|---:|---:|
|全量无缓存|60|660|0|0.018334 s|
|按目标无缓存|60|540|0|0.017358 s|
|按目标及有效缓存|60|180|360|0.018106 s|

全部被请求检查的工具输出与全量基线一致。缓存组相对全量组减少约72.7%的实际工具执行，但未显示显著的总体耗时收益；本轮没有进行显著性检验。当前公式很轻，状态复制、确认、哈希和图编排的开销不能忽略。

该实验没有模型网络请求、人工操作时间或外部工程真值；20种组合来自一个模板，不是20个独立工程基准。不能用它证明模型准确性、多 Agent 优越性或完整工程安全性。

实验结果：`outputs/research/mechanism_ablation.json` 与同名 Markdown。简要证据另保存于 `docs/validation/consultation_mechanism_summary.json`，便于纳入版本管理；完整 outputs 目录仍可按原仓库规则忽略。

## 3. 使用

原端口8511已有旧服务，本轮新版本在本机8512启动：

```powershell
conda activate engiagent
python -m streamlit run streamlit_app.py --server.port 8512 --server.address 127.0.0.1
```

打开 `http://127.0.0.1:8512`。

### 咨询示例

1. 在设计工作台加载“已有梁独立验算”，确认并运行。
2. 进入“专家咨询”，可以提问：
   - 为什么抗弯通过仍需要检查长期挠度？
   - 当前裂缝为什么不通过？
   - 哪些工具复用了缓存？
   - 梁高改为600mm。
   - 活载改为6kN/m。
3. 明确修改会生成参数建议，点击“将建议写入待确认草稿”。
4. 回工作台核对、确认、运行，查看修订和局部重算。

离线咨询采用明确标记的有限规则，支持“参数改为数值单位”等赋值。自由表述采用 DeepSeek。相对增减、代词、冲突条件会要求明确最终参数，不会猜测。当前直接采用设计内力的任务不允许仅改荷载后沿用旧内力；应另建荷载任务或明确更改设计内力。

### 重现机制实验

```powershell
python examples/run_mechanism_experiment.py
```

网页“对照实验”也可显式点击“运行机制对照实验”，再下载真实报告。页面切换或再次渲染不会重复运行实验。原四组人工/通用LLM/固定程序/完整系统的正式对照仍标为未执行。

## 4. 验证证据

- 完整回归：**155 passed in 19.11s**。随后仅调整咨询表格显示顺序和数值格式，未改变计算内核。
- 真实 DeepSeek：三次受控请求分别验证解释、梁高0.6m与活载6kN/m的双参数修改、模糊活载要求的澄清。精确核对修改字段与标准化数值后才确认测试案例；局部与全量工具输出一致。审计在 `outputs/research/consultation_live_audit.json`。
- 新测试覆盖原文缺失、字段错配、数值错配、单位错配、跨参数借用单位/数值、歧义、否定、陈旧建议、重复采用、未确认运行、API异常、实际配筋保留、未请求检查及审计导出。
- Streamlit AppTest 覆盖咨询→采用→确认→重算、所有页面导航不重复调用，以及机制实验显式执行/只读重渲染。
- 最终浏览器实际验收：加载完整新设计并运行，提出“梁高改为600mm”，页面准确显示550→600mm原文建议；采用后运行按钮被确认关口保护，人工确认后转已有梁验算。保留3Φ20，得到抗弯容量173.872kN·m、裂缝0.130718mm、长期挠度8.428843mm，五项请求检查通过，完整审查仍为未完成。网页还显式启动了真实机制对照。
- 实测截图：`outputs/research/screenshots/consultation_proposal.jpg`。截图来自最终页面，不是界面设计稿。浏览器操作使用 computer-use 技能的浏览器控制流程。

## 5. 当前边界与后续

本版没有扩展原工程公式和规范支持范围，没有新增自动学习、OCR、持久化恢复、多候选最优搜索。针对不同失败项的策略指导已区分，但核心自动改设仍是原来的有限动作集。

下一步应增加独立工程参考案例、自然语言批量测试、人机确认对照与模型角色消融。若追加外部经验学习，需隔离经验集和测试集，并以未见案例验证，而不是将咨询历史当作已学会策略。
